# 聊天文字调色（SillyTavern 扩展）

给酒馆聊天消息改色的 UI 扩展：主要文本、斜体文本、引用文本三类文字可**分别**调色，支持「跟随主题 / 纯色 / 渐变」，渐变可自定义 2~4 个颜色与角度、带霓虹光晕开关与强度，并内置 10 套配色预设与 3 套可保存的自定义预设。面板跟随酒馆主题与字体大小。

## 安装

1. 把本文件夹整体复制到酒馆的用户扩展目录：

   ```
   SillyTavern/data/<你的用户名>/extensions/聊天文字调色/
   ```

   最终结构为：`extensions/聊天文字调色/manifest.json`、`index.js`。

2. 重启酒馆（或刷新页面）。
3. 进入 **扩展（Extensions）→ 管理扩展**，确认「聊天文字调色」已启用。
4. 打开 **扩展设置**，找到「聊天文字调色」面板开始配置。

## 功能对照

| 需求 | 实现 |
| --- | --- |
| 只改聊天消息 | 染色仅作用于 `#chat` 内的消息，不碰角色卡、设置等其他界面；代码块（行内 `code`、`pre`）保持原样 |
| 插件总开关 | 面板顶部「启用聊天文字调色」开关，一键停用/恢复；停用后聊天保持酒馆原生样式 |
| 三类文字横排切换 | 面板顶部横排「主要文本 / 斜体文本 / 引用文本」标签，逐类设置 |
| 跟随酒馆主题 | 每个类别都提供「跟随主题」模式，不做任何处理；面板配色、字体大小跟随酒馆 |
| 纯色 | 可选任意颜色（色块 + Hex 输入 + 取色器） |
| 渐变 | 自定义 2~4 个颜色（可添加/移除），角度 0~360° 可调 |
| 光晕 | 渐变模式下有「霓虹光晕」开关与强度（0~100%）；逐字三层 `text-shadow` 辉光，每个字散发自己颜色的光晕（蓝段蓝光、白段白光、黄段黄光） |
| 流式实时渐变 | 流式生成期间就走与结束后**同一套**逐字染色：每个新字一出现就拿到自己的颜色和同色光晕；每来一段只追加新字并原地重算，不拆已有 span，所以不会出现「这一帧有光、下一帧没光」的闪烁 |
| 单一发光来源 | 一条消息只要被逐字染色，元素本身的渐变/滤镜就全部让位（元素级规则带 `:not([data-yyx="1"])` 互斥），颜色和光晕只由每个 span 的 `text-shadow` 承担；调强度只重刷 span 样式，不会拆掉它们 |
| 渐变粒度 | 主要文本 = 整条消息；**斜体 = 每对 `*xxx*`（一个 `em`）独立循环**；**引用 = 每个引号内对话独立循环**（引号外叙述保持酒馆原色，按字符顺序首→尾） |
| 内置预设 | 10 套配色预设位于配色设置下方；点击套用：斜体与引用应用渐变并开启光晕（强度 100%），主要文本改为跟随主题 |
| 自定义预设 | 3 套可保存槽位，调好配色点「存入」，点「使用」一键切换 |
| 取色器 | 参考常见拾色器：色板（饱和度/明度）+ 色相条；右侧依次为色值预览、Hex、RGB 与确定按钮，实时联动 |

## 使用说明

- **切换类别**：点击顶部标签（主要文本 / 斜体文本 / 引用文本），下方显示该类别的配置。
- **配色模式**：跟随主题 / 纯色 / 渐变，切换后显示对应选项。
- **渐变颜色**：每行「色块 + Hex 输入 + 调色板按钮」，点击调色板按钮展开取色器；最多 4 色、最少 2 色，可点「＋添加颜色」在末尾前插入中间色，「－」移除。
- **光晕**：勾选「霓虹光晕」后出现强度滑块；每个字单独散发「该字颜色」的三层 `text-shadow` 光晕（贴字亮边 + 中层 + 外晕），强度控制光晕半径与透明度，100% 即原始霓虹参数；低强度档仍保留可见辉光，强度拉到 0 或关闭光晕则完全无光。
- **内置预设**：点击色卡即套用（斜体与引用应用渐变并开启光晕 100%，主要文本改为跟随主题），套用后可再逐类微调。
- **自定义预设**：调好某一类别的渐变配色后点「存入」保存到槽位；点「使用」把配色套用到斜体与引用，主要文本改为跟随主题。
- **总开关**：面板顶部勾选「启用聊天文字调色」生效；取消勾选即停用（聊天保持原生样式），再次勾选恢复配色。
- **实时生效**：修改后即时重染可见与后续消息；流式生成期间以元素级完整渐变 + 光晕近似呈现，生成结束后自动逐字校正为每字同色光晕，观感一致。
- 「重新渲染可见消息」手动清理残留染色并重载配色样式；「全部恢复跟随主题」一键还原（自定义预设槽位保留）。

## 设计说明

- **光晕观感**：每个字单独上色并单独发光——文字先按渐变方向逐字取色，再给每个字加同色三层 `text-shadow`（贴字 `2px/1.0`、中层 `8px/0.85`、外晕 `24px/0.50`），蓝段蓝光、白段白光、黄段黄光；以最高优先级（!important）写入，避免被主题样式覆盖。
- **性能**：
  - 逐字染色按需触发（设置变化 / 生成结束 / 消息进入视口），流式期间走元素级渐变近似兜底，避免高频重建与闪烁；
  - 主要文本按字符在渐变方向上的真实位置投影取色；斜体每对 `*xxx*`、引用每对引号各自按字符顺序线性取色（首→尾），跨行连续、方向不反转；引用引号外叙述不染色；
  - 光晕为逐字 `text-shadow`，不创建 filter 合成层，长文本性能更稳。

## 注意事项

- 若同时启用了带光晕/渐变的 UI 主题：主题对 `q`/`blockquote` 自带的光晕与渐变会与插件效果叠加，建议二选一，或在插件中关闭对应光晕。
- 斜体与引用嵌套时，以斜体的设置优先（斜体文字按斜体规则染色）。
- 若「主要文本」设为渐变、而斜体/引用为「跟随主题」：主要文本整条渐变会作用于整条消息，斜体/引用文字也会呈现主要文本的渐变；如需各司其职，请为斜体/引用分别选择纯色或渐变（推荐直接使用内置预设，主要文本会自动设为跟随主题）。
- 流式输出期间即逐字染色（与结束后同一套），新增字符只追加、不重建已有 span，不再有「先近似、后校正」的切换过程。
- 建议配合酒馆设置：开启 **No Blur**、关闭「流式淡入」动画，观感更稳定。

## 版本

v1.2.1（修流式闪烁：同一帧内同步补染）
- 真机截图确认了闪烁的确切成因：**无光的那一帧是元素级路径，有光的那一帧是逐字路径**。也就是说在该设备上只有逐字 span 的 `text-shadow` 真能发光，元素级 `filter: drop-shadow` 不出光。而酒馆每吐一个 chunk 都会整段重写消息正文，把 span 抹掉；旧版是延迟 60ms 防抖才补染，中间那几帧就落到了「元素级、不发光」的路上 → 有光/无光交替。
- 改法：把补染搬进 MutationObserver 回调里同步执行。MO 回调在浏览器绘制之前运行，因此渲染出来的每一帧都是「逐字上色 + 逐字光晕」，中间态根本不会上屏。
- 结构还在（只是文字变多）时走增量补染，已有 span 原地复用、不重建；结构被整段抹掉时才整体重染。
- 加了文本指纹（`MES_SIG`）：自己写入 DOM 会产生回声回调，指纹一致且仍有 span 时直接忽略，既防「重染→再触发→重染」死循环，也省掉无谓的重排。
- 长消息（>2200 字）不逐 chunk 同步重排，退回 60ms 防抖，避免手机端卡顿。
- 同步重染全程 try/catch，异常不会中断后续 chunk，最坏情况退回防抖 + 元素级兜底。

v1.2.0（重构：彻底改为「一条消息只有一个发光来源」）
- **症状根因**：旧版同一条消息上并存两套上色与两套发光——元素级 `background-clip:text` 渐变 + `filter: drop-shadow`，以及逐字 span 实色 + `text-shadow`。哪一套生效取决于「这条消息此刻有没有逐字 span」，而流式每个 chunk 都会让 span 有无反复变化，于是出现你反馈的三个现象：开局只有元素级近似（短文本只取到首色段，看着发淡）、流式期间光晕在两套机制间来回切换（一闪一闪）、调强度时先拆 span 再重建（中间那一帧两套都不生效，光晕消失）。
- **重构口径**：以逐字 span 作为唯一载体，颜色与光晕都写在每个字自己的 span 上；元素级渐变与 `filter` 只保留给「尚未逐字染色」的消息做过渡，并加 `:not([data-yyx="1"])` 与逐字染色严格互斥，两者永远不会同时作用于同一条消息。
- 已染色的消息追加一条中性规则（`background:none`、`background-clip:border-box`、`-webkit-text-fill-color:currentColor`、`text-shadow:none`、`filter:none`），保证祖先元素不会用文字裁剪层把子 span 的光晕一起裁掉。
- 流式改为增量染色：`paintStreamChunk` 不再只贴元素级兜底标记，而是直接逐字上色——已有 span 原地复用（组号 `data-yyxG` 与引号状态按元素续接），只给新出现的文字补 span，再对整条消息重算一次样式（带样式缓存，只写真正变色的字）。
- 设置改动分两类处理：模式/色标/角度变了才重建 span（`structSig` 结构签名判定）；只改强度、光晕开关或纯色时**原地重刷**每个 span 的 `text-shadow`，绝不拆 span，因此拖强度不会再出现光晕掉一帧的现象。
- 调试采样改为取**最新的两条消息**并附全局计数（总消息数、已染色条数、span 总数、屏幕附近未染色数）。旧版一直抽样最早的消息，而那些消息通常在视口外、按设计就不染色，导致诊断里长期显示 `spanCount: 0`，掩盖了真实状态。
- 升版为 1.2.0（行为与实现均重构）。
